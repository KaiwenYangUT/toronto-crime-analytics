## Data frame and feature contract

`Final_Project.Rmd:30–295`, `model.Rmd:28–254`, `scripts/prepare_project_data.R:6–158`, and `scripts/build_visual_widgets.R:9–165` provide the input and merge details.

1. Read CSVs in this exact order: Auto Theft, Bicycle Thefts, Break and Enter, Homicides, Robbery, Shooting and Firearm Discharges, Theft Over. `bind_rows(..., .id="Dataset")`; positive is `MCI_CATEGORY == "Robbery"`. The historical code does **not** explicitly apply the new four-category whitelist. Categories lacking required MCI/location/date fields disappear through missing-value handling; export surviving categories and exclusions in P2 rather than infer them from the seven input filenames.
2. Convert `OCC_MONTH` with `match(..., month.name)`; construct `Occurrence_Time` using `as.POSIXct(..., format="%Y-%m-%d-%H")` without explicit timezone. Obtain weekdays from that timestamp, Sunday=1 through Saturday=7. Host timezone/DST and English weekday locale matter, including missing timestamps at DST gaps. Use occurrence year **2020 only**, and drop neighbourhood `NSA`.
3. Retained incident fields: category, robbery indicator, occurrence timestamp, year, month, weekday, hour, neighbourhood, location type, premises type, longitude and latitude. Season: March–May Spring, June–August Summer, September–November Fall, otherwise Winter. Darkness is hour ≥18 or <6; it is a fixed clock rule, not measured sunset. Legacy model/widgets use integer 0/1; the newer shared preparation uses logical values.
4. Census workbook uses 2021 neighbourhood profiles with 2020 income columns. `model.Rmd:121–225` lists exact selected spreadsheet column names and aliases. Derived fields: permanent positions / labour force; transport workers / population; healthcare workers / population; absolute individual average-minus-median income. A household count is formed by summing seven overlapping household columns, then source columns are removed; do not reinterpret the sum or repair overlap during parity.
5. Seven census spelling substitutions (`model.Rmd:242–249`, shared helper `145–151`): O`Connor Parkview→O'Connor-Parkview; Danforth-East York→Danforth East York; Taylor Massey→Taylor-Massey; East End Danforth→East End-Danforth; Cabbagetown-South St. James Town→Cabbagetown-South St.James Town; North St. James Town→North St.James Town; Yonge-St. Clair→Yonge-St.Clair.
6. Important variant: historical model/Final_Project assigns `income2020 <- na.omit(income_2020)` but merges the **unfiltered** `income_2020`, after `na.omit(crime_2020)`. Shared preparation and widget builder apply `na.omit()` to the **merged full frame**. The newer helper also explicitly removes missing coordinates. A later subset can thus yield different missingness semantics; compare actual exported frames.
7. `merge(..., by="Neighbourhood", all.x=TRUE)` sorts under R collation. Split sampling therefore depends on locale/row order even with a seed. Preserve duplicate rows and compare multiset identity separately from row order. The original code has no explicit cross-category deduplication.
8. Model frame (`Final_Project.Rmd:373–386`, `model.Rmd:310–321`) removes Neighbourhood, category, timestamp, year, and location type. Response plus **17 predictors** remain: Month, Day_Of_Week_Numeric, Hour, Premises_Type, Longitude, Latitude, Season, Darkness, Individual_Median_Income, Individual_Average_Income, Population, Average_Household_Size, Number_of_Rental_Properties, Permanent_Job_and_Labour_Force_Ratio, Transportation_Service_Worker_and_Population_Ratio, HealthCare_Service_Worker_and_Population_Ratio, Difference_in_Individual_Median_Average_Income. Do not include neighbourhood ID itself as a predictor.

## Models and evaluation contract

All formulas are `Robbery ~ .` on the 17-predictor frame. `Final_Project.Rmd:390–403`: `set.seed(123)`, `sample(nrow(final_data), .7*nrow(final_data))`, no stratification, neighbourhood grouping, or temporal holdout. Response is factor FALSE/TRUE. Confusion matrices orient **rows actual / columns predicted**, positive TRUE or 1. Accuracy is diagonal sum / total; precision TP/(TP+FP), recall TP/(TP+FN), harmonic F1. No bootstrap confidence intervals, PR-AUC, threshold tuning or calibration were reported.

## Contradictions, caveats and faithful-port checklist

The following are original messages to preserve in the parity record and flag before correcting in the improvement phase; they must not become unqualified new-site claims.

- **Summer / winter / holidays:** visual `54–56,85`, report pp.7–8/12. Published winter robbery=872, summer=564; month peaks March=355, January=353, February=335. Holiday effects are not separately tested. The captions' broad summer/holiday conclusion exceeds these data.
- **Weekends:** visual `57,85`, report pp.5/8/12. Published Friday and Saturday tie at 443 robberies; Sunday is lowest at 332. Report p.5 says Saturday and Thursday have higher total counts, but published Wednesday=2609, Friday=2587 exceed Saturday=2233. Preserve chart, flag text.
- **Darkness:** visual `42,59,85`, report pp.7–8/12. Repeated-neighbourhood box data do not estimate individual risk or a premises-specific robbery count. The hour arrays imply dark share about 16.4% vs daylight 17.2% (planning claim; exact fresh results still required). Fixed 18:00–06:00 ignores season/date; cannot equate with measured sunset.
- **Hourly shape:** report p.5 claims a normal distribution at midnight and declines from 1AM→11AM and 1PM→11PM. Published total-count arrays have nonmonotonic changes (noon=791, 11AM=413; 8PM=1038). V0 refreshed caption is more cautious; keep branch variants explicit.
- **Spatial/causal/safety claims:** README `6–16`, index `19–23,43–49,73–86`, model `264,360`, visual `42,113`, report pp.1/9–13 contain personal safety, causal influence, prevention and place/time risk language. New product describes association/classification among reported incidents. Neither empty map areas nor model precision establishes victimization risk or safety.
- **Information leakage / generalization:** the original random split shares neighbourhood census attributes and nearby coordinates across train/test. Report p.12 explicitly acknowledges 2020-only data, COVID-specific events, census time gaps, and geography limited to Toronto's 158 neighbourhoods. No grouped or later-year generalization estimate exists.
- **Construct caveats:** report p.13 acknowledges fixed sunrise/sunset, simplistic employment ratios, rental counts not normalized by population/density/area; these must survive the migration. Census income is for 2020 despite a 2021 census source. Same neighbourhood attributes repeat on incident rows; summary statistics are incident-weighted. High Gini importance is not evidence of causality or successful feature engineering by itself.
- **Source versus paper model mismatch:** report p.10 advertises the unused XGB grid as actual hyperparameters; source `798–823` proves it is not passed. Seed reset is absent for bagging/RF/GBM; caret/xgboost versions and earlier RNG use matter. Code comments claim trees/RF do not output probabilities (`530,694`); this is a historical comment, not a valid model limitation.
- **Refresh differences:** active F1 aggregates 158 neighbourhood points versus repeated old points; F3/F4 aggregate before plotting versus old per-incident merges, reducing duplicate marks. Active F4 opacity .55 differs from old .5; selected branch widgets are authoritative for presentation. `variable.Rmd` replaces four old horizontal bar panels with three bars plus an hourly line; use the refreshed chart type for the chosen branch and retain old variant in parity provenance.
